SDI Live (SameDay): deploy guide

For James. Andy's briefing tool: an account manager talks or types a brief and gets SDI's past work, concept renders, a GA and the brief pack. Updated 2 November 2026.

In short: copy SDI_Automation\ from this folder to C:\SDI_Automation\ on the server, create the Python environment (the keys file .env comes with the folder, nothing to fill in), then start brief_lite\lite_app.py (port 5020) and craft\craft_site.py (port 5030).

2. What the server needs

  • Windows 10/11 or Windows Server, with Python 3.11 (64-bit).
  • Outbound internet to api.openai.com, api.anthropic.com (and api.x.ai if Grok is used), plus normal web access for the moodboard's product search.
  • Read access to W: and K: for SDI's past work pictures. The tool never writes to them.
  • A GPU is optional. It speeds up picture matching and transcription; CPU works.
  • Ports 5020 (Same Day) and 5030 (SDI Craft) open on the SDI network.

cd C:\SDI_Automation

.venv-gpu\Scripts\python.exe -m pip install -r "K:\IT\AI & Automation\Design\SDI Same Day Intelligence\requirements_full.txt" --extra-index-url https://download.pytorch.org/whl/cu128
rem the keys file came with the folder - check it is there (do not edit it):
dir C:\SDI_Automation\.env

No NVIDIA GPU? Install torch for CPU instead: drop the --extra-index-url, and if pip complains about +cu128, remove that suffix from the torch lines.

Keep the path C:\SDI_Automation. Several files read C:\SDI_Automation\.env and C:\SDI_Automation\studio_data\ by that exact path. If it has to live elsewhere, search the code for C:\SDI_Automation first.

4. Start it

C:\SDI_Automation\.venv-gpu\Scripts\python.exe C:\SDI_Automation\brief_lite\lite_app.py
C:\SDI_Automation\.venv-gpu\Scripts\python.exe C:\SDI_Automation\craft\craft_site.py

Then open http://SERVER:5020. The first start takes about 30 seconds while it loads the picture-matching model; "past-work search ready" in the console means it's up.

Keep it running: on the laptop, Studio_Brief_Autostart.bat (in the Startup folder) starts everything and restarts anything that stops. On a server, either run the two commands as Windows services (for example with NSSM), or create Task Scheduler tasks "At startup", "Run whether user is logged on or not", and restart on failure.

6. Costs and limits

Daily capstudio_data\ai_switch.json → "brief_lite_daily_cap_usd": 10.0. When a day's spend reaches it, the AI stops until midnight. Edit and save; no restart needed.
Typical spendAbout $2–3 for a full brief (voice call, first render at high quality, changes at medium, GA, moodboard, voice-note replies). $0 on days nobody uses it. Claude's share is billed on the Anthropic account, the rest on OpenAI.
Voice modelEveryone uses the big live model (gpt-realtime), with gpt-4o-transcribe writing out what the AM says. Voice notes: heard by gpt-4o-transcribe (free Whisper as backup), answered in gpt-4o-mini-tts voice "fable" (free Microsoft voice as backup). Design director: claude-opus-5-5.
Stop buttonThe ■ Stop in the chat stops any new render, so no more credit is spent. A picture already being drawn still finishes (it's already paid for) and appears under Images.

7. Check it works

  1. http://SERVER:5020 opens and shows "Who's briefing?".
  2. http://SERVER:5020/api/status answers.
  3. Type a short brief in a test project. A reply comes back and the "AI spend today" counter moves.
  4. http://SERVER:5030 opens SDI Craft.

8. If something goes wrong

Chat answers "budget is used up"Raise brief_lite_daily_cap_usd in studio_data\ai_switch.json.
No replies at allCheck .env has ANTHROPIC_API_KEY and OPENAI_API_KEY, and that the server can reach the APIs.
Mic or voice doesn't workThe page must be opened over HTTPS (see section 5), and the browser must be allowed the microphone.
"SDI made this before" is emptybrief_lite\projects.db is missing, or W:/K: can't be read.
